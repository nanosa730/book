# 分析レコードの形式

`analysis/records/batch-XXXX.jsonl` に、**1投稿 = 1行のJSON** で記録する。

JSONL にする理由：1193本を人が読むためではなく、集計するため。
人が読む形（テーマ別の一覧など）は `tools/report.py` が生成する。

---

## フィールド

| キー | 必須 | 型 | 内容 |
| --- | --- | --- | --- |
| `id` | ● | string | `day-0001` 形式。全投稿で一意 |
| `day` | ● | int \| null | Day番号。不明なら `null` |
| `date` | | string \| null | `YYYY-MM-DD`。不明なら `null` |
| `source` | ● | string | 元ファイルと位置（例 `posts/batch-0001.md`） |
| `event` | ● | string | **第1層** 何が起きたか。事実だけ。1〜2文 |
| `insight` | ● | string | **第2層** なのさが書いている気づき。本文に根拠がある範囲で |
| `view` | ● | string | **第3層** その奥にある人生観。編集室の読み |
| `basis` | ● | `stated` \| `implied` | `view` が本文に書かれているか、読み取ったものか |
| `question` | | string | この投稿が扱っている問い（明示・暗黙どちらも） |
| `themes` | ● | string[] | `analysis/vocabulary.md` にあるタグのみ |
| `quotes` | | string[] | 印象的な原文。**一字も変えない** |
| `strength` | ● | 1〜5 | なのさ自身の心の動きの強さ（下の目安参照） |
| `promise` | ● | `promise` \| `reframe` \| `neither` | **この投稿は「良くなる」と約束しているか**（下記参照） |
| `unsaid` | ● | string | **この投稿が触れかけて、触れなかったこと。** 無ければ `""`（下記参照） |
| `counter_evidence` | ● | string | 本の核の仮説に **合わない** 点。無ければ `""` |
| `story_seed` | | string | 物語のどの場面に変換できそうか。思いつかなければ `""` |
| `links` | | string[] | 関連する他投稿の `id` |
| `notes` | | string | なのさに確認したいこと、迷ったこと |

---

## `promise`（本の結末を決める欄）

執行草舟は「希望」を悪徳とする。一方、引き継ぎ書 17. の目指す読後感は
「明日の朝、少しだけ違う景色が見えるかもしれない」。
**この二つが衝突するかどうかが、本の最後の一行を決める**
（`docs/10_希望という問題.md`）。

そして、それは1193本を読めば分かる。各投稿に問う：

> **この投稿は、読者に「良くなる」と約束しているか。**

| 値 | 意味 | 例 |
| --- | --- | --- |
| `promise` | **状況が良くなる** と言っている | 「きっと報われる」「いつか実を結ぶ」「大丈夫、何とかなる」 |
| `reframe` | **状況は変わらないが、見え方が変わる** と言っている | 「同じ景色が違って見える」「そういう見方もある」 |
| `neither` | どちらでもない。ただの記録や描写 | |

集計結果の意味：

- `promise` が多い → **衝突は本物。** 執行草舟とは相容れない道を選ぶことになる
- `reframe` が多い → **なのさの文体は、最初から絶対負と両立していた**

**これが PHASE 2 の最重要検証項目。** 迷ったら `neither` ではなく、
どちらに近いかを考えてから決める。

## `unsaid`（最重要の欄）

本の核——**「人生は不幸でも良い。そう思えるか」**——は、
1193本のどこにも書かれていない。なのさが意図的に扱わなかった
（`docs/08_なぜ物語でなければならないか.md`）。

だから、頻度を数えても核は出てこない。**核は空白の側にある。**

そこで各投稿に問う：

> **この投稿は、何に触れかけて、触れなかったか。**

- 話がそこへ向かいかけて、別の方向へ折れた
- 強い言葉が出かけて、やわらかい言葉に置き換わった
- 具体的な出来事を書いたのに、その一番痛い部分だけ書いていない
- 明るく締めくくっているが、締めくくらなければ別の結論になりそうだった

そういう跡があれば書く。無ければ `""`。

**触れかけて引き返した場所が、物語の始点になる。**

---

## `strength` の目安

**本にとっての重要度ではない。** 文章そのものの熱量。

| 値 | 状態 |
| --- | --- |
| 1 | 淡々とした記録。心の動きがほとんど見えない |
| 2 | 気づきはあるが、いつもの調子 |
| 3 | はっきり心が動いている |
| 4 | 言葉を選んでいる跡がある。書きにくそうに書いている |
| 5 | 明らかに他と違う。何かを打ち明けている |

4 と 5 は後で必ず読み返す。ここに、まだ言葉になっていない思想がある可能性が高い。
**`strength` 4〜5 の投稿は、そのまま `unsaid` の候補でもある。**
書きにくそうに書いているのは、書けないものの近くにいるからだ。

## 記入例

```json
{"id":"day-0412","day":412,"date":"2024-06-15","source":"posts/batch-0009.md","event":"山に登ったが、天候が崩れ、頂上を目前にして引き返した。","insight":"引き返す判断ができたことを、あとから誇らしく思った。登頂だけが成功ではない。","view":"続けることだけが正しさではない。やめることも、自分で選んだのなら一つの選択である。","basis":"implied","question":"諦めることは、負けることなのか。","themes":["勇気ある撤退","失敗","人生の選択","物事の見方を変えること"],"quotes":["下りながら、負けた気はしなかった。"],"strength":4,"promise":"reframe","unsaid":"「登頂しなかった」ことは書いているが、「そのとき何を諦めたのか」は書いていない。撤退の話に見せて、失ったものの話を避けている。","counter_evidence":"「思い通りにならなかった」という書き方をしていない。不本意さより、選び取った感覚のほうが強い。","story_seed":"主人公が、周囲の期待を裏切って何かを途中でやめる場面。","links":[],"notes":"この「撤退」の話は他にもありそう。何回書いているか要確認。"}
```

---

## ルール

- `quotes` は引用。**絶対に整えない。** 誤字も改行もそのまま。
- `view` に自信がないときは、それでも書く。ただし `notes` に「自信なし」と書く。
  空欄にすると、後で「読めなかった」のか「読まなかった」のか区別できない。
- `counter_evidence` を空欄にするのは、本当に反証が無いときだけ。
  1バッチ50本で反証がゼロなら、読み方が仮説に引きずられている。
- `unsaid` は無理に埋めない。読み取れないのに書くと、ただの創作になる。
  ただし1バッチで一件も出ないなら、投稿の表面しか読んでいない可能性がある。
- タグは語彙表にあるものだけ。無ければ先に語彙表へ追加する。
