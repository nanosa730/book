# 分析の方法（PHASE 2〜4）

1193本以上を読む。手当たり次第に読むと、必ず途中で「読み方」がぶれる。
先に方法を決めてから読み始める。

---

## 1．三層で読む

引き継ぎ書 9. の「具体的な出来事 → 気づき → 人生観」を、そのまま作業単位にする。

| 層 | 問い | 例（登山での勇気ある撤退） |
| --- | --- | --- |
| 第1層　出来事 | 何が起きたか | 山に登ったが、途中で引き返した |
| 第2層　気づき | なのさの心はどこで動いたか | 引き返す判断は、負けではなかった |
| 第3層　人生観 | その奥にある、人生についての考え | 続けることだけが正しさではない／やめる勇気も選択である |

**第3層は推測である。** 推測であることを必ず記録する（`stated` / `implied`）。
なのさが実際に書いた言葉は第2層まで。第3層は編集室の読みであり、
後でなのさに確認して初めて確定する。

---

## 2．思い込みを防ぐための手順

「人生とは不幸なものである」という仮説を持ったまま1193本を読むと、
**合う投稿だけが目に入る。** これは避けなければならない（引き継ぎ書 15.）。

### 手順として組み込む安全装置

1. **先に読み、後で解釈する。**
   各バッチを読むときは、仮説を参照しない。
   まず出来事・気づき・言葉を記録し、解釈は記録の後で行う。

2. **反証欄を必須にする。**
   すべての投稿に `counter_evidence` 欄がある。
   「この投稿は仮説に合わない」「むしろ人生を肯定的に見ている」と思ったら必ず書く。
   **反証が一件も出ないバッチは、読み方を疑う。**

3. **頻度と強度を分ける。**
   よく出るテーマ ＝ 根っこ、とは限らない。
   1回しか書いていないが、明らかに熱量が違う文章がある。
   `strength`（1〜5）で、なのさ自身の心の動きの強さを別に記録する。

4. **明示と推測を分ける。**
   「なのさが書いたこと」と「なのさが書いていないが読み取れること」を混ぜない。
   本の核になるのは後者かもしれないが、混ぜた瞬間に検証できなくなる。

5. **時系列を捨てない。**
   1193本は数年分ある。Day1のなのさと今のなのさは同じ考えとは限らない。
   思想が **変化した跡** そのものが、物語の心の変化の設計図になる可能性がある。
   だから Day番号・日付は必ず残す。

   これは抽象的な用心ではなく、**具体的に検証したいことがある。**
   「人生とは不幸なものである」の出どころは執行草舟だと判明した
   （`docs/07_思想の源泉_執行草舟.md`）。
   ならば問える——**執行草舟に出会う前と後で、文章は変わっているか。**

   - 変わっていない → 執行草舟は発見ではなく **言語化**。
     もともとなのさの中にあったものに名前がついた。本の核に据えてよい。
   - 変わっている → 外から来た思想。なぜ強く惹かれたのか、そちらを掘る。

   時系列が残っていれば、これは推測ではなく **観察** になる。

6. **定期的な較正。**
   200本ごとに、過去バッチからランダムに20本を再読し、
   同じ分類になるか確認する。ずれていたら語彙表を見直す。

## 2.5　最初に「読み方の答え合わせ」をする

原文は少しずつ届く。この形には利点がある。
**1193本を読み終えてから「読み方が違った」と気づくのが、いちばん避けたい事態。**

だから、最初の数本で必ず答え合わせをする。

1. 最初に届いた 3〜5本を分析する。
2. その第3層（人生観の読み）を、そのままなのさに見せる。
3. 聞く。**「これは、なのさが本当に思っていたことですか？」**
4. ずれていたら、読み方を直す。語彙表も直す。
5. 合っていたら、そのまま進む。

これを較正バッチ（最初の100本）のあいだ、20〜30本ごとに繰り返す。
100本を超えたら、頻度を下げてよい。

**第3層は編集室の推測にすぎない。** なのさの確認を経て初めて材料になる。
確認していない読みは、`basis` が `implied` のまま残り続ける。

## 3．語彙のコントロール

1193本に自由にタグを付けると、集計できない。
「学び」「学ぶこと」「学習」が別タグになった時点で、PHASE 3 は失敗する。

- タグは `analysis/vocabulary.md` の表にあるものだけを使う。
- 表にないタグが必要になったら、**表に追加してから**使う。追加した理由も書く。
- 最初の100本は「較正バッチ」とする。読み終えたら語彙表を作り直してよい。
  それ以降は、追加はしても削除・改名は慎重に行う（過去の記録を直す必要が出る）。

---

## 4．作業単位

- 投稿は `posts/` に、50本前後のバッチファイルとして置く。
- 分析結果は `analysis/records/batch-XXXX.jsonl` に、1投稿1行で書く。
- 形式は `analysis/schema.md`。
- 一度に全投稿をコンテクストに載せない。1バッチずつ読む。
- 1バッチ読み終えるごとに、`docs/04_進行状況.md` に
  「このバッチで気づいたこと」を3行だけ書く。**あとで読み返すのはこの3行。**

## 5．PHASE 3：繰り返しから思想を取り出す

集計（機械的）と解釈（人間的）を分ける。

### 集計（`tools/report.py` が出す）
- タグの頻度
- タグの共起（一緒に現れるテーマの組）
- 年ごとの推移（思想が変化しているか）
- `strength` が高い投稿の一覧
- `counter_evidence` が書かれた投稿の一覧

### 解釈（ここが本題）
集計は材料にすぎない。問うのは常にこれ：

> **なのさは、なぜ何度もこの話を書いているのか？**

やること：

1. **「言い換えの束」を作る。**
   話題はまったく違うのに、同じことを言っている投稿を集める。
   （向日葵の話と、生徒の質問の話と、学会の話が、同じことを言っているかもしれない）
2. その束に **名前をつける。** これが思想の候補になる。
3. その名前が、なのさ自身の言葉で言えるかを確認する。
   編集室の言葉でしか言えない束は、まだ思想として熟していない。
4. **一度も書かれていないこと** を探す。
   1193本のあいだ、なのさが避けている話題・触れていない領域には意味がある。

## 6．PHASE 4：思想地図

テーマを並べるのではなく、つながりを描く。

- **ノード** ＝ 思想（PHASE 3 で名前をつけた束）
- **エッジ** ＝ 関係。3種類だけ使う。
  - `→`　because（Aだから、Bと考える）
  - `⇄`　tension（AとBは、なのさの中で緊張関係にある）
  - `＝`　rephrase（AとBは、言い方が違うだけ）

構造は三層：

```
根（1つ）      … 心晴日和のいちばん奥にある考え
 └ 幹（3〜5）   … 根から直接出ている考え
    └ 枝        … 具体的なテーマ
```

**tension（⇄）が最も重要。**
矛盾しているように見える二つの考えが、なのさの中に同居している場所——
そこが、物語の主人公が悩む場所になる。
きれいにつながる思想からは、物語は生まれない。

成果物は `docs/03_思想地図.md`。

---

## 7．やらないこと

- 投稿に点数をつけて「良い投稿」を選ぶこと（引き継ぎ書 3.）
- 分析中に本文を書き始めること
- 章立てを決めること（PHASE 7 まで待つ）
- 第3層の推測を、なのさに確認せずに確定させること
